When a message payload (AsyncAPI 2) or a Multi-Format Schema Object (AsyncAPI 3, on message.payload or a components.schemas entry) declares an Avro schemaFormat — i.e. its value contains application/vnd.apache.avro — that value must be exactly application/vnd.apache.avro;version=1.9.0.

Version 1.9.0 is the standard Avro schema version used across Madrid Digital and appears in every example throughout the Style Guide. Any other version string, or a missing version, is reported as an issue. schemaFormat values that are not Avro at all (e.g. a JSON Schema schemaFormat) are out of scope for this rule.

Noncompliant Code Example (AsyncAPI 2)

asyncapi: '2.6.0'
info:
  title: Carga API
  version: '1.0.0'
channels:
  carga:
    subscribe:
      message:
        schemaFormat: 'application/vnd.apache.avro;version=1.8.0'
        payload:
          type: record
          name: CargaValue
          namespace: com.example.avro
          fields:
            - name: id
              type: string

Compliant Solution (AsyncAPI 2)

asyncapi: '2.6.0'
info:
  title: Carga API
  version: '1.0.0'
channels:
  carga:
    subscribe:
      message:
        schemaFormat: 'application/vnd.apache.avro;version=1.9.0'
        payload:
          type: record
          name: CargaValue
          namespace: com.example.avro
          fields:
            - name: id
              type: string
