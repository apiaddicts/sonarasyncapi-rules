When an Avro field uses a nullable union type (e.g. ["null", "string"]), it must define default: null. Without a null default, consumers that were deployed before the field was added will fail to deserialize messages, breaking backward compatibility.

Noncompliant Code Example (AsyncAPI 2)

payload:
  type: record
  name: OrderValue
  namespace: org.example.orders
  fields:
    - name: description
      type:
        - "null"
        - string

Compliant Solution (AsyncAPI 2)

payload:
  type: record
  name: OrderValue
  namespace: org.example.orders
  fields:
    - name: description
      type:
        - "null"
        - string
      default: null
