Avro records should include a doc field at the record level to describe the purpose of the schema. This improves readability and tooling support.

Noncompliant Code Example (AsyncAPI 2)

payload:
  type: record
  name: OrderValue
  namespace: org.example.orders
  fields:
    - name: id
      type: string

Compliant Solution (AsyncAPI 2)

payload:
  type: record
  name: OrderValue
  namespace: org.example.orders
  doc: "Represents an order placed in the system"
  fields:
    - name: id
      type: string

Noncompliant Code Example (AsyncAPI 3)

asyncapi: '3.0.0'
info:
  title: Avro Record Doc
  version: 1.0.0
channels:
  orders:
    address: orders
    messages:
      OrderMessage:
        payload:
          schemaFormat: 'application/vnd.apache.avro;version=1.9.0'
          schema: # Noncompliant {{AAR046: Avro record should include the doc field with a description}}
            type: record
            name: OrderValue
            namespace: org.example.orders
            fields:
              - name: id
                type: string

Compliant Solution (AsyncAPI 3)

asyncapi: '3.0.0'
info:
  title: Avro Record Doc
  version: 1.0.0
channels:
  orders:
    address: orders
    messages:
      OrderMessage:
        payload:
          schemaFormat: 'application/vnd.apache.avro;version=1.9.0'
          schema:
            type: record
            name: OrderValue
            namespace: org.example.orders
            doc: "Represents an order placed in the system"
            fields:
              - name: id
                type: string
