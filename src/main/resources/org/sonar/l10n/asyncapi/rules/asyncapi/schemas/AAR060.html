Every message contentType must be an Avro media type that matches the glob application/*+avro (i.e. it must start with application/ and end with +avro, e.g. application/vnd.apache.avro+avro). This guarantees correct deserialization through Confluent's KafkaAvroDeserializer. The same rule applies to the document-level defaultContentType. A message that does not declare a contentType is not reported (it may rely on the defaultContentType).

Noncompliant Code Example (AsyncAPI 2)

channels:
  orders:
    subscribe:
      operationId: receiveOrder
      message:
        contentType: application/json # Noncompliant - not an application/*+avro media type
        payload:
          type: object

Compliant Solution (AsyncAPI 2)

channels:
  orders:
    subscribe:
      operationId: receiveOrder
      message:
        contentType: application/vnd.apache.avro+avro
        payload:
          type: object
