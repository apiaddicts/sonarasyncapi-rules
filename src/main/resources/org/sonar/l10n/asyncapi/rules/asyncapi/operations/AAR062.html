A consuming operation must declare a consumer group so the messaging platform can deliver its messages to a durable, load-balanced consumer that keeps track of its own position (for example, a Kafka consumer group). Every consuming operation (AsyncAPI 2 subscribe / AsyncAPI 3 action: receive) must therefore declare its consumer group, either through the x-scs-group extension (the JAPI generator extension, for example x-scs-group: alta.beca.1) or through bindings.kafka.groupId. A consuming operation that declares neither is reported. Producing operations (AsyncAPI 2 publish / AsyncAPI 3 action: send) are not reported.

Noncompliant Code Example (AsyncAPI 2)

channels:
  alta.beca:
    subscribe: # Noncompliant - the consuming operation declares no consumer group
      operationId: consumeAlta

Compliant Solution (AsyncAPI 2)

channels:
  alta.beca:
    subscribe:
      operationId: consumeAlta
      x-scs-group: alta.beca.1
  baja.beca:
    subscribe:
      operationId: consumeBaja
      bindings:
        kafka:
          groupId:
            type: string
            enum: ['baja.beca.1']

Noncompliant Code Example (AsyncAPI 3)

operations:
  consumeAlta: # Noncompliant - the receive operation declares no consumer group
    action: receive
    channel:
      $ref: '#/channels/alta-beca'

Compliant Solution (AsyncAPI 3)

operations:
  consumeAlta:
    action: receive
    channel:
      $ref: '#/channels/alta-beca'
    x-scs-group: alta.beca.1
