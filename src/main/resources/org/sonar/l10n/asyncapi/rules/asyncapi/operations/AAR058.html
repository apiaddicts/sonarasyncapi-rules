If a channel name (a channel property key in AsyncAPI 2, or a channel's address in AsyncAPI 3) contains .retry., it must follow the pattern <topicOriginal>.<consumerGroup>.retry.<n> (e.g. beca.cmd.alumnos.solicitud.beca.grupo1.retry.1), which Spring requires exactly in order to route messages for automatic retry reprocessing.

Channels whose name does not contain .retry. are not retry channels and are left untouched by this rule. This is a per-channel check: every channel that looks like a retry channel is validated individually, and one issue is reported for each one that doesn't match the required pattern.

Noncompliant Code Example (AsyncAPI 2)

asyncapi: '2.6.0'
info:
  title: Beca API
  version: '1.0.0'
channels:
  beca.cmd.alumnos.solicitud.beca.grupo1.retry.abc:
    subscribe:
      operationId: receiveSolicitudBecaRetryGrupo1
      message:
        payload:
          type: object

Compliant Solution (AsyncAPI 2)

asyncapi: '2.6.0'
info:
  title: Beca API
  version: '1.0.0'
channels:
  beca.cmd.alumnos.solicitud.beca.grupo1.retry.1:
    subscribe:
      operationId: receiveSolicitudBecaRetryGrupo1
      message:
        payload:
          type: object

Noncompliant Code Example (AsyncAPI 3)

asyncapi: 3.0.0
info:
  title: Beca API
  version: 1.0.0
channels:
  solicitudBecaRetryGrupo1:
    address: beca.cmd.alumnos.solicitud.beca.grupo1.retry.abc
    messages:
      SolicitudBecaMessage:
        payload:
          type: object

Compliant Solution (AsyncAPI 3)

asyncapi: 3.0.0
info:
  title: Beca API
  version: 1.0.0
channels:
  solicitudBecaRetryGrupo1:
    address: beca.cmd.alumnos.solicitud.beca.grupo1.retry.1
