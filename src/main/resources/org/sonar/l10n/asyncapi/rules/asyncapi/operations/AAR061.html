A Spring Cloud Stream processor is assembled by the JAPI generator from the two operations that share the same x-scs-function-name: the one that produces to a topic (AsyncAPI 2 publish / AsyncAPI 3 send) and the one that consumes from a topic (AsyncAPI 2 subscribe / AsyncAPI 3 receive). Every x-scs-function-name value used in the document must therefore be paired one-to-one between a producing and a consuming operation, so the generator links them into a single processor (for example processTopic2Topic3 declared on both). Operations that do not declare x-scs-function-name are not reported.

Noncompliant Code Example (AsyncAPI 2)

channels:
  topic2:
    publish:
      operationId: consumeTopic2
      x-scs-function-name: processTopic2Topic3 # Noncompliant - no subscribe/send shares this value
  topic3:
    subscribe:
      operationId: produceTopic3
      x-scs-function-name: processTopic3 # Noncompliant - no publish/receive shares this value

Compliant Solution (AsyncAPI 2)

channels:
  topic2:
    publish:
      operationId: consumeTopic2
      x-scs-function-name: processTopic2Topic3
  topic3:
    subscribe:
      operationId: produceTopic3
      x-scs-function-name: processTopic2Topic3

Noncompliant Code Example (AsyncAPI 3)

operations:
  consumeTopic2:
    action: receive
    channel:
      $ref: '#/channels/topic2'
    x-scs-function-name: processTopic2Topic3 # Noncompliant - no send operation shares this value

Compliant Solution (AsyncAPI 3)

operations:
  consumeTopic2:
    action: receive
    channel:
      $ref: '#/channels/topic2'
    x-scs-function-name: processTopic2Topic3
  produceTopic3:
    action: send
    channel:
      $ref: '#/channels/topic3'
    x-scs-function-name: processTopic2Topic3
