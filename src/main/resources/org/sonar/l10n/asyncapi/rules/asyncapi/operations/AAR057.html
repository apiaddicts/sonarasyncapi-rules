At least one channel in the AsyncAPI document (a channel property key in AsyncAPI 2, or a channel's address in AsyncAPI 3) must be documented as an error topic, following the pattern <topicOriginal>.[<consumerGroup>.]error.<n> (e.g. beca.cmd.alumnos.solicitud.beca.grupo1.error.1), which Spring requires exactly in order to route error messages.

The consumer group segment is only part of the name when there is more than one consumer of the original topic. The trailing numeric suffix (<n>) is mandatory. This rule is an existence check across the whole document: if no channel matches the pattern, a single issue is reported; individual channels that don't match are not flagged.

Noncompliant Code Example (AsyncAPI 2)

asyncapi: '2.6.0'
info:
  title: Beca API
  version: '1.0.0'
channels:
  beca.cmd.alumnos.solicitud.beca:
    subscribe:
      operationId: receiveSolicitudBeca
      message:
        payload:
          type: object

Compliant Solution (AsyncAPI 2)

asyncapi: '2.6.0'
info:
  title: Beca API
  version: '1.0.0'
channels:
  beca.cmd.alumnos.solicitud.beca:
    subscribe:
      operationId: receiveSolicitudBeca
      message:
        payload:
          type: object
  beca.cmd.alumnos.solicitud.beca.grupo1.error.1:
    publish:
      operationId: publishSolicitudBecaErrorGrupo1
      message:
        payload:
          type: object

Noncompliant Code Example (AsyncAPI 3)

asyncapi: 3.0.0
info:
  title: Beca API
  version: 1.0.0
channels:
  solicitudBeca:
    address: beca.cmd.alumnos.solicitud.beca
    messages:
      SolicitudBecaMessage:
        payload:
          type: object

Compliant Solution (AsyncAPI 3)

asyncapi: 3.0.0
info:
  title: Beca API
  version: 1.0.0
channels:
  solicitudBeca:
    address: beca.cmd.alumnos.solicitud.beca
    messages:
      SolicitudBecaMessage:
        payload:
          type: object
  solicitudBecaErrorGrupo1:
    address: beca.cmd.alumnos.solicitud.beca.grupo1.error.1
    messages:
      SolicitudBecaErrorMessage:
        payload:
          type: object
