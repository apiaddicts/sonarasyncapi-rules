La versión del documento AsyncAPI declarada en el campo raíz asyncapi debe ser una de las versiones permitidas por la organización. La lista de versiones permitidas es configurable mediante el parámetro allowedVersions (una lista separada por comas, por ejemplo 2.6.0,3.0.0); su valor por defecto es 2.6.0. Cuando la organización adopta una nueva versión como 3.0.0, simplemente se añade a la lista — la regla en sí no cambia. Un documento cuyo campo asyncapi falta, es nulo o está vacío no es reportado por esta regla.

Ejemplo de código no compatible (AsyncAPI 2)

asyncapi: '2.4.0'   # Noncompliant {{AAR063: La versión del documento AsyncAPI debe ser una de las versiones permitidas}}
info:
  title: Mi API Asíncrona
  version: '1.0.0'
channels:
  /pets: {}

Solución compatible (AsyncAPI 2)

asyncapi: '2.6.0'
info:
  title: Mi API Asíncrona
  version: '1.0.0'
channels:
  /pets: {}

Ejemplo de código no compatible (AsyncAPI 3)

# Con el valor por defecto allowedVersions = "2.6.0", un documento 3.0.0 se reporta
asyncapi: '3.0.0'   # Noncompliant {{AAR063: La versión del documento AsyncAPI debe ser una de las versiones permitidas}}
info:
  title: Mi API Asíncrona
  version: '1.0.0'

Solución compatible (AsyncAPI 3)

# Añade 3.0.0 al parámetro allowedVersions (allowedVersions = "2.6.0,3.0.0")
asyncapi: '3.0.0'
info:
  title: Mi API Asíncrona
  version: '1.0.0'
