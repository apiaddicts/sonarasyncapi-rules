Se recomienda agregar el esquema de seguridad que se va a usar a cada canal

Ejemplo de código no compatible (AsyncAPI 2)

asyncapi: '2.4.0'
info:
  title: Unique Operation ID Example API
  version: '1.0.0'
  description: API que demuestra el uso de operationId único en cada operación.
channels:
  /pets: # Noncompliant {{AAR043: El channel debe definir un esquema de seguridad en sus operaciones o bindings.}}
    subscribe:
      operationId: getPets
      message:
        contentType: application/json
        payload:
          type: object

Solución compatible (AsyncAPI 2)

asyncapi: '2.4.0'
info:
  title: Unique Operation ID Example API
  version: '1.0.0'
  description: API que demuestra el uso de operationId único en cada operación.
components:
  securitySchemes:
    apiKeyScheme:
      type: httpApiKey
      name: X-API-Key
      in: header
channels:
  /pets:
    subscribe:
      operationId: getPets
      security:
        - apiKeyScheme: []
      message:
        contentType: application/json
        payload:
          type: object

Solución compatible (AsyncAPI 3)

asyncapi: '3.0.0'
info:
  title: Secure Channel
  version: '1.0.0'
servers:
  default:
    host: api.example.com
    protocol: wss
components:
  securitySchemes:
    api_key:
      type: apiKey
      in: header
      name: X-API-Key
channels:
  secureEvents:
    address: secure/events
    messages:
      Event:
        payload:
          type: object
