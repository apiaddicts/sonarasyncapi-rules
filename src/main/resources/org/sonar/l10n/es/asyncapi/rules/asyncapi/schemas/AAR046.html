Los registros Avro deberían incluir un campo doc a nivel de registro para describir el propósito del esquema. Esto mejora la legibilidad y el soporte de las herramientas.

Ejemplo de código no compatible (AsyncAPI 2)

payload:
  type: record
  name: OrderValue
  namespace: org.example.orders
  fields:
    - name: id
      type: string

Solución compatible (AsyncAPI 2)

payload:
  type: record
  name: OrderValue
  namespace: org.example.orders
  doc: "Represents an order placed in the system"
  fields:
    - name: id
      type: string

Ejemplo de código no compatible (AsyncAPI 3)

asyncapi: '3.0.0'
info:
  title: Avro Record Doc
  version: 1.0.0
channels:
  orders:
    address: orders
    messages:
      OrderMessage:
        payload:
          schemaFormat: 'application/vnd.apache.avro;version=1.9.0'
          schema: # Noncompliant {{AAR046: El registro Avro debería incluir el campo doc con una descripción}}
            type: record
            name: OrderValue
            namespace: org.example.orders
            fields:
              - name: id
                type: string
