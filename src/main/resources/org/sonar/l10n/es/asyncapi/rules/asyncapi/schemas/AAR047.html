Los campos Avro deberían incluir un atributo doc para describir el propósito de cada campo. Esto mejora la visibilidad del esquema y la comprensión por parte de los consumidores.

Ejemplo de código no compatible (AsyncAPI 2)

payload:
  type: record
  name: OrderValue
  namespace: org.example.orders
  fields:
    - name: id
      type: string

Solución compatible (AsyncAPI 2)

payload:
  type: record
  name: OrderValue
  namespace: org.example.orders
  fields:
    - name: id
      type: string
      doc: "The unique order identifier"

Ejemplo de código no compatible (AsyncAPI 3)

asyncapi: '3.0.0'
info:
  title: Avro Field Doc
  version: 1.0.0
channels:
  orders:
    address: orders
    messages:
      OrderMessage:
        payload:
          schemaFormat: 'application/vnd.apache.avro;version=1.9.0'
          schema: # Noncompliant {{AAR047: El campo Avro debería incluir el atributo doc con una descripción}}
            type: record
            name: OrderValue
            namespace: org.example.orders
            fields:
              - name: id
                type: string

Solución compatible (AsyncAPI 3)

asyncapi: '3.0.0'
info:
  title: Avro Field Doc
  version: 1.0.0
channels:
  orders:
    address: orders
    messages:
      OrderMessage:
        payload:
          schemaFormat: 'application/vnd.apache.avro;version=1.9.0'
          schema:
            type: record
            name: OrderValue
            namespace: org.example.orders
            fields:
              - name: id
                type: string
                doc: "The unique order identifier"
