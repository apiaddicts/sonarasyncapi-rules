El contentType de cada mensaje debe ser un tipo de medio Avro que coincida con el glob application/*+avro (es decir, debe empezar por application/ y terminar en +avro, por ejemplo application/vnd.apache.avro+avro). Esto garantiza la correcta deserialización mediante el KafkaAvroDeserializer de Confluent. La misma regla se aplica al defaultContentType a nivel de documento. Un mensaje que no declara contentType no se reporta (puede apoyarse en el defaultContentType).

Ejemplo Noncompliant (AsyncAPI 2)

channels:
  orders:
    subscribe:
      operationId: receiveOrder
      message:
        contentType: application/json # Noncompliant - no es un tipo de medio application/*+avro
        payload:
          type: object

Solución Compliant (AsyncAPI 2)

channels:
  orders:
    subscribe:
      operationId: receiveOrder
      message:
        contentType: application/vnd.apache.avro+avro
        payload:
          type: object
