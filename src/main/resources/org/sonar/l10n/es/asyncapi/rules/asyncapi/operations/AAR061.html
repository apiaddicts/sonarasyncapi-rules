El generador JAPI construye un procesador de Spring Cloud Stream a partir de las dos operaciones que comparten el mismo x-scs-function-name: la que produce hacia un topic (AsyncAPI 2 publish / AsyncAPI 3 send) y la que consume de un topic (AsyncAPI 2 subscribe / AsyncAPI 3 receive). Por tanto, cada valor de x-scs-function-name utilizado en el documento debe estar emparejado uno a uno entre una operación productora y una consumidora, para que el generador las vincule en un único procesador (por ejemplo processTopic2Topic3 declarado en ambas). Las operaciones que no declaran x-scs-function-name no se reportan.

Ejemplo Noncompliant (AsyncAPI 2)

channels:
  topic2:
    publish:
      operationId: consumeTopic2
      x-scs-function-name: processTopic2Topic3 # Noncompliant - ningun subscribe/send comparte este valor
  topic3:
    subscribe:
      operationId: produceTopic3
      x-scs-function-name: processTopic3 # Noncompliant - ningun publish/receive comparte este valor

Solución Compliant (AsyncAPI 2)

channels:
  topic2:
    publish:
      operationId: consumeTopic2
      x-scs-function-name: processTopic2Topic3
  topic3:
    subscribe:
      operationId: produceTopic3
      x-scs-function-name: processTopic2Topic3

Ejemplo Noncompliant (AsyncAPI 3)

operations:
  consumeTopic2:
    action: receive
    channel:
      $ref: '#/channels/topic2'
    x-scs-function-name: processTopic2Topic3 # Noncompliant - ninguna operacion send comparte este valor

Solución Compliant (AsyncAPI 3)

operations:
  consumeTopic2:
    action: receive
    channel:
      $ref: '#/channels/topic2'
    x-scs-function-name: processTopic2Topic3
  produceTopic3:
    action: send
    channel:
      $ref: '#/channels/topic3'
    x-scs-function-name: processTopic2Topic3
