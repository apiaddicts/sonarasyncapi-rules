Cuando un campo Avro utiliza un tipo unión anulable (por ejemplo, ["null", "string"]), debe definir default: null. Sin un valor por defecto nulo, los consumidores que se desplegaron antes de que se agregara el campo no podrán deserializar los mensajes, rompiendo la compatibilidad hacia atrás.

Ejemplo de código no compatible (AsyncAPI 2)

payload:
  type: record
  name: OrderValue
  namespace: org.example.orders
  fields:
    - name: description
      type:
        - "null"
        - string

Solución compatible (AsyncAPI 2)

payload:
  type: record
  name: OrderValue
  namespace: org.example.orders
  fields:
    - name: description
      type:
        - "null"
        - string
      default: null

Ejemplo de código no compatible (AsyncAPI 3)

asyncapi: '3.0.0'
info:
  title: Avro Optional Field Default
  version: 1.0.0
channels:
  orders:
    address: orders
    messages:
      OrderMessage:
        payload:
          schemaFormat: 'application/vnd.apache.avro;version=1.9.0'
          schema: # Noncompliant {{AAR049: Los campos opcionales de Avro (unión con null) deben declarar su valor por defecto como null}}
            type: record
            name: OrderValue
            namespace: org.example.orders
            fields:
              - name: id
                type: string
              - name: description
                type:
                  - "null"
                  - string

Solución compatible (AsyncAPI 3)

asyncapi: '3.0.0'
info:
  title: Avro Optional Field Default
  version: 1.0.0
channels:
  orders:
    address: orders
    messages:
      OrderMessage:
        payload:
          schemaFormat: 'application/vnd.apache.avro;version=1.9.0'
          schema:
            type: record
            name: OrderValue
            namespace: org.example.orders
            fields:
              - name: id
                type: string
              - name: description
                type:
                  - "null"
                  - string
                default: null
