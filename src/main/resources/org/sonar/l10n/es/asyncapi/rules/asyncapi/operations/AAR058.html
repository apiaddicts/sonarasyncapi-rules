Si el nombre de un channel (la clave de propiedad del channel en AsyncAPI 2, o el address del channel en AsyncAPI 3) contiene .retry., debe seguir el patrón <topicOriginal>.<grupo_consumo>.retry.<n> (ej.: beca.cmd.alumnos.solicitud.beca.grupo1.retry.1), que Spring requiere de forma exacta para enrutar los mensajes de reprocesamiento automático.

Los channels cuyo nombre no contenga .retry. no son channels de retry y esta regla no los afecta. Es una comprobación por channel: cada channel que parece ser de retry se valida individualmente, y se reporta una incidencia por cada uno que no coincida con el patrón requerido.

Ejemplo Noncompliant (AsyncAPI 2)

asyncapi: '2.6.0'
info:
  title: Beca API
  version: '1.0.0'
channels:
  beca.cmd.alumnos.solicitud.beca.grupo1.retry.abc:
    subscribe:
      operationId: receiveSolicitudBecaRetryGrupo1
      message:
        payload:
          type: object

Solución Compliant (AsyncAPI 2)

asyncapi: '2.6.0'
info:
  title: Beca API
  version: '1.0.0'
channels:
  beca.cmd.alumnos.solicitud.beca.grupo1.retry.1:
    subscribe:
      operationId: receiveSolicitudBecaRetryGrupo1
      message:
        payload:
          type: object

Ejemplo Noncompliant (AsyncAPI 3)

asyncapi: 3.0.0
info:
  title: Beca API
  version: 1.0.0
channels:
  solicitudBecaRetryGrupo1:
    address: beca.cmd.alumnos.solicitud.beca.grupo1.retry.abc
    messages:
      SolicitudBecaMessage:
        payload:
          type: object
