La extensión de vendor x-payload-references vincula el payload (o schema) de un mensaje con el tipo Avro que lo respalda en el registry de schemas. Puede aparecer en cualquier parte del documento — en un mensaje, en un objeto payload/schema, o en cualquier otro nivel.

Cuando existe x-payload-references, debe ser un array, y cada ítem debe definir tres campos obligatorios no vacíos, cada uno de los cuales debe además cumplir su formato esperado:

  • subject — el nombre del schema en el registry (solo caracteres válidos de subject de schema registry: letras, dígitos, ., -, _ y :).
  • ref — la URL SVN del fichero .avsc (una URL http(s), svn, svn+ssh o file que apunte a un fichero .avsc, opcionalmente con un sufijo de revisión o query).
  • referenceName — el nombre completo del tipo Avro: un namespace en minúsculas seguido de un tipo capitalizado, ej.: org.madrid.core.payload.alumnos.Ciudadano.

Ejemplo Noncompliant (formatos de campo inválidos)

x-payload-references:
  - subject: Ciudadano
    ref: no-es-url                  # no es una URL SVN que apunte a un fichero .avsc
    referenceName: cualquier_cosa   # no es un nombre de tipo Avro completamente cualificado

Ejemplo Noncompliant (AsyncAPI 2)

asyncapi: '2.6.0'
info:
  title: Scholarship API
  version: '1.0.0'
channels:
  beca.evt.alumnos.registro-bonificacion.beca:
    subscribe:
      message:
        payload:
          type: object
        x-payload-references:
          - subject: Ciudadano
            referenceName: org.madrid.core.payload.alumnos.Ciudadano

Solución Compliant (AsyncAPI 2)

asyncapi: '2.6.0'
info:
  title: Scholarship API
  version: '1.0.0'
channels:
  beca.evt.alumnos.registro-bonificacion.beca:
    subscribe:
      message:
        payload:
          type: object
        x-payload-references:
          - subject: Ciudadano
            ref: https://svn.example.com/schemas/avro/Ciudadano.avsc
            referenceName: org.madrid.core.payload.alumnos.Ciudadano

asyncapi: 3.0.0
